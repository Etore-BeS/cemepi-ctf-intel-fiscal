# Manual review CSV schema

> **Operational runbook:** [PROJECT_SOURCE_OF_TRUTH.md §6](../PROJECT_SOURCE_OF_TRUTH.md) (normalization review).  
> **Canonical script path:** `src/config/scripts.py` → `EXPORT_NORMALIZATION_REVIEW`.

Two separate CSVs support manual normalization. Rows are **frozen by frequency** (descending); do not reorder manually.

## Output paths

Generated by `scripts/movimentacoes/export_normalization_review.py`:

| File | Source table | Source column |
|---|---|---|
| `manual_review_tipo_movimentacao.csv` | `movimentacoes_delta` | `tipo_movimentacao` |
| `manual_review_tipo_sentenca.csv` | `face_processos_clean_delta` | `tipo_sentença` (JSON array, unnested) |

Round slices: `manual_review_tipo_*_r{1,2,3}.csv`.

## Memory safety

Aggregation runs in **DuckDB** over `delta_scan` with:

- Single-column projection (no full-table Polars collect)
- **Movimentação grouped by first line** (~thousands of buckets, not ~32M raw strings)
- `GROUP BY` before any materialization in Python
- Sequential processing (movimentações, then sentenças)
- Configurable `DUCKDB_MEMORY_LIMIT` (default `3GB`) and `DUCKDB_THREADS` (default `1`)

Only the small frequency table (~unique values) is enriched in Polars.

## CSV 1 — `tipo_movimentacao`

| Column | Editable | Required on close | Description |
|---|---|---|---|
| `valor_bruto` | No | — | First line of `tipo_movimentacao` (review bucket key) |
| `frequencia` | No | — | Row count in base for this bucket |
| `percentual_base` | No | — | Share of all non-null values (%) |
| `exemplo_contexto` | No | — | Sample full raw text from bucket (truncated to 240 chars) |
| `normalizado_proposto` | Yes | — | Auto: same as `valor_bruto` (first line) |
| `normalizado_final` | Yes | Yes | Canonical label; default `__NAO_MAPEADO__` |
| `status_revisao` | Yes | Yes | `pendente`, `aprovado`, `descartar`, `duvida` |
| `observacoes` | Yes | When `duvida` | Free text |
| `revisor` | Yes | On approve | Reviewer id |
| `data_revisao` | Yes | On approve | ISO-8601 UTC |

## CSV 2 — `tipo_sentença`

| Column | Editable | Required on close | Description |
|---|---|---|---|
| `valor_bruto` | No | — | TJSP sentence label |
| `frequencia` | No | — | Unnested occurrence count |
| `percentual_base` | No | — | Share of all sentence labels (%) |
| `normalizado_proposto` | Yes | — | Auto: same as `valor_bruto` |
| `normalizado_final` | Yes | Yes | Canonical label |
| `resultado_processo` | Yes | Yes | `favoravel`, `desfavoravel`, `inconclusivo` |
| `credito_recuperado` | Yes | Yes | `sim`, `nao`, `inconclusivo` |
| `confianca_regra` | Yes | — | `alta`, `media`, `baixa` (auto rule confidence) |
| `status_revisao` | Yes | Yes | Same enum as movimentação |
| `justificativa` | Yes | When not obvious | Short rationale |
| `revisor` | Yes | On approve | Reviewer id |
| `data_revisao` | Yes | On approve | ISO-8601 UTC |

## Guardrails

1. Never edit `valor_bruto` or `frequencia`.
2. Use `__NAO_MAPEADO__` instead of empty cells for unmapped `normalizado_final`.
3. Re-export with merge preserves manual columns matched on `valor_bruto`.
4. Use `--no-merge` only for a clean slate.
